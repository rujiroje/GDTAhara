## 2. Business Context

### 2.1 Source Data

**BOM Files provided by user (SAP Export):**

|---|---|---|---|---|
| `1_FG_New.xlsx` | `fert new` | 5,266 | 569 | 750 |

### 2.2 Material Types (SAP Standard)

| Type | Meaning | Example |
|---|---|---|
| **FERT** | Finished product | EBOTG0170A (B.OTOKI) |
| **HALB** | Semi-finished (Blow molded before packaging) | BFFT070CG |
| **ROH** | Raw material | NPP4, EVOH-F, ADS-P674S |
| **VERP** | Packaging | CAPP20 (carton), BAPT5050 (plastic bag) |
| **SCAP** | Scrap generation (**negative quantity!**) | SPP4F1GF31-NP |
| **UNBW** | Non-valuated (marker) | #CAPP12 |
| **HIBE** | Operating supply | — |

### 2.3 BOM Excel Structure

Per row (BOM line item, 22-25 columns):
```
Material Group · Alt.No · FG Code · Item# (10/20/30) · FG Name ·
RM Code · RM Name · Plant · Per Unit · %Loss · BomStatus · Mat Type
```

### 2.4 Key Business Rules

1. **BOM is Flat (Single-level)** — SAP has already exploded the BOM.
   FG rows contain ROH/VERP directly, no intermediate HALB references.
2. **Scrap has Negative Quantity** — SAP convention. Example: `-4.368 KG`
3. **Monthly Update** — BOM changes ~1x per month max
4. **Alternative BOMs** — 1 FG may have multiple recipes (alt_no 1, 2, ...)
5. **Plant-specific** — Plant 5100 is Tahara; ASB uses different plant code
6. **Effective Dating** — historical production must reference historical BOM

### 2.5 User Answers (Requirements Confirmation)

| Question | Answer | Design Impact |
|---|---|---|
| BOM source? | SAP Export (Excel) | Manual upload UI, no real-time sync |
| Change frequency? | ≤ 1x per month | Simple effective_from/to model |
| Auto material calc? | **YES — critical value** | Must implement MaterialRequirementService |
| Scrap usage? | Track variance (over-usage) | Must implement BomVarianceService |
| Timeline concern? | Don't want Phase 1 to stall | Insert W12.5, delay only 2-3 weeks |

### 3.3 Recipe Module Decision

**Recipe stays separate from BOM.**

- **Recipe** = Machine parameters (temperature, cycle time, pressure) — how to run the machine
- **BOM** = Material composition (raw materials, packaging) — what materials to use

They complement each other and don't overlap.

## 4. Database Schema Changes

### 4.1 New Tables (3 tables)

#### 4.1.1 `bill_of_materials` (BOM Header)

```sql
CREATE TABLE bill_of_materials (
    id                    BIGINT IDENTITY(1,1) NOT NULL,
    fg_code               NVARCHAR(50)   NOT NULL,
    alternative_number    INT            NOT NULL CONSTRAINT df_bom_alt DEFAULT 1,
    plant_code            NVARCHAR(20)   NOT NULL CONSTRAINT df_bom_plant DEFAULT '5100',
    material_group        NVARCHAR(50)   NULL,
    sap_material_type     NVARCHAR(10)   NULL,
    base_quantity         DECIMAL(12,4)  NOT NULL CONSTRAINT df_bom_baseq DEFAULT 1,
    unit                  NVARCHAR(10)   NOT NULL CONSTRAINT df_bom_unit DEFAULT 'PCS',
    effective_from        DATE           NOT NULL,
    effective_to          DATE           NULL,
    status                NVARCHAR(20)   NOT NULL CONSTRAINT df_bom_status DEFAULT 'ACTIVE',
    imported_from_file    NVARCHAR(200)  NULL,
    imported_at           DATETIME2      NOT NULL CONSTRAINT df_bom_imp_at DEFAULT SYSUTCDATETIME(),
    imported_by           BIGINT         NOT NULL,
    created_at            DATETIME2      NOT NULL CONSTRAINT df_bom_created DEFAULT SYSUTCDATETIME(),

    CONSTRAINT pk_bill_of_materials PRIMARY KEY (id),
    CONSTRAINT uk_bom_fg_alt_plant_effective
        UNIQUE (fg_code, alternative_number, plant_code, effective_from),
    CONSTRAINT fk_bom_imported_by FOREIGN KEY (imported_by) REFERENCES users(id)
);
GO

CREATE INDEX idx_bom_fg_status ON bill_of_materials(fg_code, status);
CREATE INDEX idx_bom_effective ON bill_of_materials(effective_from, effective_to);
```

#### 4.1.2 `bom_item` (BOM Lines)

```sql
CREATE TABLE bom_item (
    id                    BIGINT IDENTITY(1,1) NOT NULL,
    bom_id                BIGINT         NOT NULL,
    item_number           INT            NOT NULL,
    rm_code               NVARCHAR(50)   NOT NULL,
    rm_name               NVARCHAR(200)  NULL,
    quantity_per          DECIMAL(12,4)  NOT NULL,
    unit                  NVARCHAR(10)   NOT NULL,
    loss_percent          DECIMAL(5,2)   NULL,
    material_type         NVARCHAR(10)   NOT NULL,
    is_scrap              BIT            NOT NULL CONSTRAINT df_bi_scrap DEFAULT 0,
    bom_status            INT            NOT NULL CONSTRAINT df_bi_status DEFAULT 1,
    notes                 NVARCHAR(500)  NULL,

    CONSTRAINT pk_bom_item PRIMARY KEY (id),
    CONSTRAINT uk_bom_item_bom_seq UNIQUE (bom_id, item_number),
    CONSTRAINT fk_bom_item_bom FOREIGN KEY (bom_id) REFERENCES bill_of_materials(id)
);
GO

CREATE INDEX idx_bi_bom ON bom_item(bom_id);
CREATE INDEX idx_bi_rm_code ON bom_item(rm_code);
CREATE INDEX idx_bi_scrap ON bom_item(is_scrap) WHERE is_scrap = 1;
```

### 4.3 View for Query Performance

```sql
CREATE OR ALTER VIEW v_plan_material_requirement AS
SELECT
    pp.id                        AS plan_id,
    pp.plan_date,
    pp.machine_id,
    pp.product_id,
    p.product_code,
    pp.target_qty,
    bi.rm_code,
    bi.rm_name,
    bi.material_type,
    bi.unit,
    bi.quantity_per,
    bi.is_scrap,
    (pp.target_qty * bi.quantity_per) AS planned_quantity,
    (pp.target_qty * bi.quantity_per * ISNULL(bi.loss_percent, 0) / 100.0)
                                       AS planned_loss_quantity
FROM production_plan pp
JOIN products p          ON pp.product_id = p.id
JOIN bill_of_materials b ON b.fg_code = p.product_code
                          AND b.status = 'ACTIVE'
                          AND (b.effective_to IS NULL OR b.effective_to >= pp.plan_date)
                          AND b.effective_from <= pp.plan_date
JOIN bom_item bi         ON bi.bom_id = b.id;
GO
```

### 6.5 W12.5e — Variance Analysis Service (1 MD)

- [ ] Create `service/BomVarianceService.java`
- [ ] Method: `List<VarianceDto> analyzeForReport(Long reportId)`
- [ ] Logic:
  - Get ProductionReport → get plan_id → get planned requirement (call MaterialRequirementService)
  - For each RM in planned:
    - actualQty = SUM(material_stock_transactions WHERE report_id = ? AND rm_code matches BOM)
    - variance = actualQty - plannedQty
    - variancePercent = (variance / plannedQty) × 100
  - Threshold rules:
    - `abs(variancePercent) <= 5%` → GREEN (OK)
    - `abs(variancePercent) 5-10%` → YELLOW (WARNING)
    - `abs(variancePercent) > 10%` → RED (ALERT)
- [ ] Method: `List<VarianceDto> analyzeScrap(Long reportId)`
  - planned_scrap from BOM items where is_scrap = 1
  - actual_scrap from scrap_weight_log table
  - Same threshold logic
- [ ] Method: `List<VarianceSummaryDto> aggregateByDateRange(LocalDate from, LocalDate to)`
  - Group by rm_code, sum variances

### 8.1 Initial Data Load (One-time)

```
Step 1: Backup GDTahara database (DBA action)
Step 2: Deploy V10-V12 migrations (auto via Flyway on Spring Boot start)
Step 3: Login as Admin
Step 4: Navigate to BOM Upload page
Step 5: Upload FG file (5,266 rows) → wait ~30-60 sec
Step 6: Upload SEMI file (818 rows) → wait ~10-20 sec
Step 7: Verify bom_import_log:
        - Expect ~6,000+ rows added total
        - 0 errors (or acceptable minor errors documented)
Step 8: Spot check: search "EBOTG0170A" → should show 8 items matching Excel
```

### 8.2 Monthly Update (Recurring)

```
1st of month workflow:
1. SAP export new BOM Excel
2. Admin uploads via BOM Upload page
3. System auto:
   - Compares with existing active BOMs (by fg_code + alt_no + plant)
   - For each FG:
     * If BOM identical to existing active → skip (log as skipped)
     * If BOM changed:
       - Set old BOM.effective_to = last day of previous month
       - Insert new BOM with effective_from = today
       - Copy BomItems for new BOM
   - Log summary to bom_import_log
4. New Production Plans automatically use new BOM (via view WHERE clause)
5. Historical Reports still reference old BOM (via effective_from/to date range)
```

### 8.3 Edge Case Handling

| Case | System Behavior |
|---|---|
| Same file re-uploaded | Detect via filename + hash → mark all rows as skipped |
| FG code not in `products` table | Auto-create Product with `sap_material_type = FERT`, log warning |
| RM code not in `materials` table | Auto-create Material with detected `material_type`, log warning |
| Alternative BOM (alt_no > 1) | Import all → PC selects active alt via UI (default alt_no = 1) |
| Scrap items (negative qty in Excel) | Store absolute value + set `is_scrap = 1` |
| Row with `#` prefix in RM code | Recognize as SAP marker (e.g., UNBW) — import as-is |
| Corrupted Excel structure | Reject with detailed error, log to `errors_json` |

```sql
-- Get active BOM for a specific FG
SELECT b.fg_code, b.alternative_number, b.effective_from,
       bi.item_number, bi.rm_code, bi.rm_name, bi.quantity_per, bi.unit, bi.is_scrap
FROM bill_of_materials b
JOIN bom_item bi ON b.id = bi.bom_id
WHERE b.fg_code = 'EBOTG0170A'
  AND b.status = 'ACTIVE'
  AND b.effective_to IS NULL
ORDER BY bi.item_number;

-- Material requirement for tomorrow's plans
SELECT rm_code, rm_name, material_type, unit,
       SUM(planned_quantity) AS total_needed,
       SUM(planned_loss_quantity) AS total_loss
FROM v_plan_material_requirement
WHERE plan_date = CAST(DATEADD(day, 1, GETDATE()) AS DATE)
  AND is_scrap = 0
GROUP BY rm_code, rm_name, material_type, unit
ORDER BY rm_code;

-- BOM change history for an FG
SELECT fg_code, alternative_number, effective_from, effective_to,
       imported_from_file, imported_at, u.username AS imported_by
FROM bill_of_materials b
JOIN users u ON b.imported_by = u.id
WHERE fg_code = 'EBOTG0170A'
ORDER BY effective_from DESC;
```
